# 多模型分工约定

本文是 CokeAI 项目里多模型协作的固定分工。适用于本仓库所有后续任务，除非用户当次明确改口。

## 角色

| 角色 | 模型 | 职责 |
|---|---|---|
| 大脑 | `glm-5.3-flash` | 方案评审、把关、安全审查。改动的最终检查者。 |
| 主力 | `deepseek-flash` | 批量编码、独立成块的实现（如 Chrome 扩展、脚手架、批量重构）。 |
| 主会话 | Grok（当前 agent） | 架构决策、后台接口、核心业务逻辑、集成、测试、上线、与用户对话。 |

## 怎么拆活

1. **主会话先做架构与接口契约**：先定数据流、API 形状、安全边界，写成明确的文字，再交给子代理。
2. **独立成块的实现给 deepseek-flash**：给它完整上下文（API 契约、文件路径、验收标准、硬性红线），让它后台写完报告回来。典型：Chrome 扩展、一次性脚本、批量迁移。
3. **核心业务逻辑主会话自己写**：支付、订单状态机、脱敏、鉴权这些碰红线的代码不外包。
4. **glm-5.3-flash 做评审**：feature 分支提交前，把 diff 和设计要点交给 glm 做安全与逻辑评审，意见回到主会话处置。
5. **子代理用后台模式**跑，主会话同时推进自己的部分，两者汇合后再 typecheck + 测试。

## 已知红线（子代理 prompt 里必须带上）

- 货源采购保持人工付款；不接货源 `/shared` 代理 API；不绕过 ESA 滑块。
- 服务器不存货源登录态；凭据只进服务器 `.env`。
- 扩展回填必须人工确认，不自动发送。
- `main` 只走 PR；「直接上线」需用户明示。

## 当前在跑的例子

- 采购回填扩展（`extensions/cokeai-procure/`）：deepseek-flash 写扩展，主会话写 capture 后台（`src/lib/shop/capture.ts`、`/api/admin/shop/capture/*`、队列页门槛 SHOP_CAPTURE_MIN_QUEUE=7），glm-5.3-flash 合并前评审。
