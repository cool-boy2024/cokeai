## 已上线（作为基线）

- 应用层：商品详情页按 IP 统计**不同** slug（20 个/60 秒，收紧时 10）；列表页 60 次/分钟/IP + 20 个**不同** `category|q|page` 视图；搜索引擎 UA 豁免；Redis 故障 fail-open。
- 展示层：列表页销量/库存粗粒度（`已售 260+ · 仅剩少量`），详情页保持精确。
- 图片：`/api/shop/images/*` Referer 白名单（空 Referer 放行 + 本站 + 常见分享/搜索平台），不加 `Vary: Referer`。**2026-11-19 修复缓存投毒**：403 一度被 Cloudflare 缓存一年（任何人带外站 Referer 先请求一次，图片对所有人变 403），现在 403/404 都是 `no-store`，只有 200/206/304 才 immutable。注意这只在缓存未命中时生效。
- 边缘：Cloudflare 免费版唯一一条速率规则 `shop-rate-limit`，`/shop*` 10 秒 > 30 次/IP → Block 10 秒。

## P0 — 下一次动代码就做

### 1. IPv6 按 /64 聚合限流

**为什么**：2026-11-19 黑盒测试发现同一台设备同时有多个 IPv6 前缀（`2001:da8:203d:9c:…` 与 `2001:da8:2036:7c:…`），Cloudflare 按单地址计数时会被摊薄。应用层的 `sec:*:<ip>` key 也是单地址，脚本换隐私地址就能重置额度。

**怎么做**：在限流 key 生成处把 IPv6 归一到 /64（取前 4 组），IPv4 保持不变；Redis 里原 key 保留一个版本周期，避免重启瞬间全部放行。注意 `/admin/security` 展示的 Top IP 仍用完整地址，只聚合**计数**。

**验收**：同一 /64 内轮换 30 个源地址请求商品页，仍触发 429；正常用户（一个 /64 = 一台路由器）不受影响。

### 2. 应用层渐进惩罚（指数退避）

**为什么**：Free 版边缘只能封 10 秒，等于没有惩罚。应用层现在也只有 429，冷却时间固定。

**怎么做**：Redis `sec:penalty:<ip>` 记连续触发的次数和截止时间；第 1 次 1 分钟 → 2 → 4 → 8 → 封顶 30 分钟；连续 30 分钟无触发才清零。命中时直接返回 429 + `Retry-After`，并在 `/admin/security` 显示「累计惩罚 IP 数」。

**验收**：脚本连续触发 5 轮后冷却到 8 分钟以上；真人误触一次只停 1 分钟。

### 3. 列表页视图检测实际不触发，需要重做

**为什么**：2026-11-19 黑盒实测，从 65 个连续 `/shop?q=zN` 请求全程 200，一次 429 都没出现。原因是两个阈值叠加：60 次/分钟的固定窗口 TTL 从窗口第一个请求开始算，跨洋客户端一个窗口只发得进 25–35 个请求；而视图计数要等第 20 次请求之后才开始记，剩下的 5–15 个视图永远到不了 21。只有同城低延迟、约 40+ 次/分钟且不跨窗口的爬虫才会被拦。

**怎么做**（择一或组合）：
- 把 `SHOP_LIST_PROBE_AFTER` 从 20 降到 5–10，或者直接从第 1 个请求就开始记不同视图（Redis 调用成本很低，`zadd` + `zcard`）；
- 或者把「不同视图」和「固定窗口」合并成滑动窗口决策，避免 TTL 边界把计数冲掉；
- 改完用 30–40 个不同 `q`/`page` 组合、间隔 1.5–2 秒复测，必须在 30 次以内触发 429。

**验收**：从国内家中宽带（约 1.5 秒/请求）连续翻 30 个不同视图能被拦；正常顾客翻 3–5 页不受影响。

## P1 — 有条件再做

### 4. 升级 Cloudflare Pro 后重配边缘

Pro 才能给到：更长的封禁时长、`Managed Challenge` 动作、按路径分区的多条规则、排除 `/v1` 和支付回调。升级后把 `shop-rate-limit` 改成 10 分钟 + Managed Challenge，并单开一条更宽的低速爬虫规则。

### 5. 把 Cloudflare 命中数接进 `/admin/security`

用只读 API Token 调 Cloudflare GraphQL Analytics，按天拉 `rate limiting` 命中数，和站内 429 放同一张图上。**Token 只放服务端环境变量，不进仓库、不进浏览器。**

### 6. 列表页深度翻页上限

`page` 超过某个值（例如 20）时，要求登录或加一次轻量验证。理由：店铺只有几十个商品，真人翻不到那么深，深翻基本是镜像行为。

## 明确不做（别再提）

| 方案 | 为什么不做 |
|---|---|
| 价格移出 HTML | 破坏首屏、SEO 和分享预览，收益只有「价格多活一天」 |
| slug 全量改哈希 | 破坏外链、书签、已收录页面，收益低于成本 |
| Referer 一刀切 | 微信/Telegram 预览、图片搜索全部裂图，正常分享先受伤 |
| 全站开 Bot Fight Mode | 免费版不能按路径排除，会挑战 `/v1` 和支付回调 |
| 自定义静态 429 页 | 运营明确不要；现在 429 + `Retry-After` 已够用 |
| 全站 Anubis PoW | 正常顾客多等几秒，用订单换防护 |
| 阻断搜索引擎 UA | 等于自断收录，只做豁免，不做拦截 |
