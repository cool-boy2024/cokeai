# CokeAI 采购回填助手（Chrome MV3）

把货源站（`zyanai.cc`、`ai-buy.vip`，同一套 tokyo 店）付款成功后显示的卡密，回填到
CokeAI 小店订单的浏览器扩展。运营仍然在自己的浏览器里登录货源站、自己付款；扩展只做
「抓取 → 人工确认 → 回填」这一段。

## 为什么需要它

小店的数字商品要先到货源站下单付款，货源站返回卡密，运营再复制回本站后台。中间全靠
手工复制粘贴，容易贴错单、贴漏、贴到别的订单上。

把货源站登录态放到服务器上自动代购风险太高：账号密码、验证码、风控都要长期保存在服务
端。这个扩展反过来做——**票（货源登录态）只在运营自己的浏览器里**，服务器只知道
「哪个订单已经交付、交付了什么字段」。扩展拿到的本站令牌 12 小时有效，只存在
`chrome.storage.session` 里，浏览器关闭即消失。

## 工作方式

```text
本站后台页 (cokeai.cc.cd/admin/*)
  └─ content-cokeai.js  同源 POST /capture/token、/capture/enabled
        │ CAPTURE_TOKEN / CAPTURE_GATE
        ▼
background.js  ── 每 30 秒 GET /capture/queue（Bearer 令牌）──► 本站 API
        ▲                                                    │ 队列 / 角标 / 通知
        │ CDK_FOUND（只含 fields、pageUrl、supplierOrderRef）  ▼
content-supplier.js (zyanai.cc / ai-buy.vip)             popup.html（人工确认）
```

- 扩展从不发送货源站 cookie，也不上传整页 HTML；只上报提取出的交付字段、来源页 URL 和货源单号。
- 回填必须点「回填到本站」才会发送，不会自动提交，避免贴错订单。
- 队列为空、未达门槛、令牌失效时，扩展不会做任何破坏性动作，直接走原来的人工流程。

## 加载

1. 打开 `chrome://extensions`。
2. 右上角打开「开发者模式」。
3. 点「加载已解压的扩展程序」，选择本目录 `extensions/cokeai-procure`。
4. 打开（或刷新）`https://cokeai.cc.cd/admin` 下任意后台页，扩展会自动取令牌。
   工具栏图标出现数字表示有队列，出现「填」表示抓到了卡密等待确认。

升级代码后回到 `chrome://extensions` 点扩展卡片上的刷新按钮，再刷新已经打开的后台页。

## 日常流程（四步）

1. **打开后台采购队列页**，保持至少一个本站后台标签页开着。扩展靠它同源取令牌；
   令牌 12 小时有效，后台页常开时会自动续。
2. 在队列里点「开始采购（自动回填）」。订单会标记为等待回填（30 分钟窗口），并跳到
   对应货源页。
3. **在货源站付款**。付款成功页出现卡密后，扩展自动抓取，工具栏角标变成「填」。
4. 点扩展图标，确认抓到的字段，选择要回填的订单，点 **「回填到本站」**。成功后本站
   会像人工粘贴一样保存交付内容、写事件并通知客户。

只有第 3 步的抓取是自动的；第 4 步永远需要人工点击。

## 门槛

本站 `SHOP_CAPTURE_MIN_QUEUE`（默认 7）控制是否启用自动回填：待采购积压达到门槛才建议
用扩展接管，否则后台页和弹窗都会显示「未达门槛 depth/min」，继续人工采购即可。这个值
由服务端返回，扩展只负责展示。

## 设置

弹窗底部「设置」里可以改 **API Base**，默认 `https://cokeai.cc.cd`，本地开发填
`http://localhost:3000`，保存在 `chrome.storage.sync`。队列轮询和回填请求都发到这个
地址；令牌由后台页所在域名签发，两者不一致时弹窗会提示，按提示把 Base 调成与后台页
相同的域名即可。

## 文件

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | MV3 清单：权限、后台脚本、两条内容脚本、弹窗 |
| `background.js` | 存令牌、30 秒轮询队列、角标/通知、接收抓取结果、确认后回填 |
| `content-cokeai.js` | 本站后台页同源取令牌与门槛，转交后台脚本 |
| `content-supplier.js` | 货源站启发式抓卡密（可见文本、表格、code、只读输入、复制按钮） |
| `popup.html` / `popup.css` / `popup.js` | 队列展示、抓取结果确认、设置 |
| `icons/icon128.png` | 工具栏与通知图标 |

## 抓取规则

- 关键词：卡密、兑换码、CDK、激活码、卡号、卡號、密码。
- 取值：含至少 8 位字母数字的片段；来自只读输入框、`code` 等专用值容器时保留完整文本
  （邮箱、带符号密码不截断）。`卡号` + `密码` 成对出现时写两个字段，如
  `{"卡号":"...","密码":"..."}`。
- 同一页多次渲染只上报一次相同内容；SPA 异步加载由 `MutationObserver` 兜住。
- 抓不到时完全静默，不弹通知、不改变角标。

## 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 弹窗显示「未连接本站后台」，队列一直空 | 没有有效令牌。打开或刷新 `https://cokeai.cc.cd/admin` 任意后台页；确认当前浏览器已用管理员账号登录。令牌 12 小时过期后也要这样重取。 |
| 弹窗显示「令牌已失效」 | 管理员在别处重新登录/被撤销，或令牌过期。重新打开后台页即可。 |
| 显示「未达门槛 depth/min」 | 待采购单数低于服务端门槛，扩展不介入，按原流程人工采购。 |
| 货源站付款成功但抓不到卡密 | 货源站改版或字段换了位置。先回退到「手动复制卡密 → 后台订单里粘贴交付」，再把页面截图/结构反馈给维护者更新启发式规则。 |
| 角标有数字但通知没出现 | 通知只在队列数量变化时触发；Chrome 系统通知被静音时也会看不到，以角标和弹窗为准。 |
| 抓到的值不对/缺字段 | 不要点确认。手动回填这单，避免错单。 |
| 扩展更新后弹窗报错 | 在 `chrome://extensions` 刷新扩展，并刷新已打开的本站后台页。 |

## 本地开发

`content-cokeai.js` 只注入 `https://cokeai.cc.cd/admin/*`。要在 `http://localhost:3000`
调试取令牌流程，需要临时把 `manifest.json` 第一条 `content_scripts.matches` 加上
`http://localhost:3000/admin/*`（host_permissions 已包含该地址），调试完记得改回，避免
误提交。

## 数据边界

- 令牌：`chrome.storage.session`，只由后台脚本通过 Bearer 头使用。
- 队列缓存、待确认字段：同样在 `chrome.storage.session`，关浏览器即清。
- API Base：`chrome.storage.sync`，只存一个地址字符串。
- 不发货源 cookie，不发整页 HTML，不发截图，不写 `localStorage`。
